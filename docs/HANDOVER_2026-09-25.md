## 2. 产品范围与不能丢的基线

- 以用户提供的 1.8.1 界面为常用页面的视觉和交互基线，同时保留后来新增的聚合首页、聚合搜索、NAS 和本地音乐。
- 主导航由 `ATMusic/RootView.swift` 管理；“精选”页也在此文件。首页/平台聚合内容主要在 `ATMusic/DiscoverView.swift`。
- 在线服务包含网易云、QQ、酷狗等接口；聚合搜索、来源筛选、歌手/专辑/歌单详情不能只显示首屏数据。新增平台应复用来源模型与能力分层，不要把平台分支写死在通用 UI 中。
- NAS 支持连接、曲库/文件夹/歌手/专辑/歌单、搜索、播放，以及标签、封面、歌词编辑。写入成功必须回读核对，不能只凭接口返回“成功”提示。
- 三套播放器（经典、Apple Music、唱片）、歌词/评论/队列和布局编辑预览都需要保持一致。改播放器时分别回归封面页与歌词页。
- 歌曲连续列表统一采用紧凑行样式，主要组件为 `ATMusic/SongCell.swift`。

## 4. 构建、测试和安装边界

在项目目录运行：

```sh
./xcodegen/bin/xcodegen generate --spec project.yml
xcodebuild -project ATMusic.xcodeproj -scheme ATMusic -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath /tmp/atmusic-handover-sim CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY='' build
```

本轮精选字色修改只做了源码检查与模拟器编译，**尚未做修复后真机视觉回归**。下次测试请依次检查浅色、深色及自定义强调色下的“精选”分类：选中与未选中文字均可读，切换分类后仍可加载歌单，滑动分类条不卡顿。

真机签名与安装流程见 `docs/HANDOVER_SIGN_INSTALL.md`，但其历史验证记录不能代替本轮验证。打包/安装前确认 Bundle ID、版本号、描述文件和目标设备；勿把证书、描述文件、NAS 凭据写入仓库。原版 AT Music 的安装不应与独立的 DS Music (`com.atmusic.nas`) 混淆。

  `~/Library/Mobile Documents/com~apple~CloudDocs/Documents/IPA/`
  （Finder 中对应 iCloud Drive → 文稿 → IPA）
- 项目根目录新增 `copy_unsigned_ipa_to_icloud.sh`，用于复制并校验 SHA-256。
- `package_at_music_ipa.sh` 已接入该脚本；以后通过该脚本封装无签名 IPA 时会自动复制到 iCloud。
- 如果以后采用手工 `xcodebuild + Payload + zip/ditto` 的方式生成无签名 IPA，也必须在封包完成后执行：
  `./copy_unsigned_ipa_to_icloud.sh <无签名IPA路径>`

## UI 修改全局检查规则（2026-09-25 起强制）

任何看似局部的 UI / 交互修改，都必须同时做以下检查，不能只修当前页面：

1. 四套 UI 风格都要验证：`liquid`（默认液态）、`clear`（磨砂玻璃）、`compact`（紧凑淡雅）、`nativeClean`（Apple 简洁）。
2. 先查是否已有全局组件；选择器优先复用 `ATMusicSelectableSurface` + `atmusicSelectionForeground`，按钮优先复用 `GlassPressButtonStyle` / `GlassButton`。
3. 同语义控件必须全局搜索：例如“播放全部 / 随机播放 / 聚合 / 平台切换 / 编辑 / 选择器”，不能只改用户截图所在页面。
4. 每个可点击主操作至少同时有视觉反馈；设置允许触感时还要有 haptic。
5. 涉及列表、播放状态或频繁 `@Published` 更新时，要检查 SwiftUI 行 identity、隐式动画和动态 symbolEffect，避免抖动/闪屏。
6. 修改完成后至少做：全项目同类模式扫描 + 四 UI 启动验证 + Simulator Debug build；准备交付时再做 iPhoneOS Release 无签名构建。
