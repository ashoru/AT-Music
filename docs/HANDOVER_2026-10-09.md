## 1. 项目概览

开源 SwiftUI 音乐播放器，多平台浏览/搜索/播放/歌词/下载/NAS 播放，高度可配置播放器。支持中英双语。仓库即完整客户端源码。

技术要点：
- 工程用 **xcodegen**（`project.yml`）生成 `.xcodeproj`；`Swift 5.0`；iOS 26.0；bundle id `com.atmusic.player`。
- 有 `ATMusicWatch`（watchOS target）与 `tests/`，多数迭代只改 iOS target。
- 平台接口均为**非官方逆向接口**，仅供个人自用，接口可能变动或被风控（见“关键约定”）。

## 4. 核心架构与数据流

### 4.1 入口与导航
`ATMusicApp.swift` → `RootView.swift`。Root 用系统 `TabView`（搜索 role / tabBarMinimizeBehavior / tabViewBottomAccessory），MiniPlayer 挂 `tabViewBottomAccessory`。主导航是**路由（openRoute）**驱动，路由类型含 `dailySongs([Song])` 等。

### 4.2 主页 `DiscoverView`
- **板块**由 `SectionOrderStore` 管理，默认顺序 `["每日推荐", "最近播放", "排行榜"]`，可自定义排序并持久化。
- 平台切换：单平台（网易/QQ/酷狗/NAS）+ **聚合首页**（`isHomeAggregate`，多平台合并展示）。启用哪些平台由 `PlatformPreferenceStore` 的 `homeProviders` 决定。
- **每日推荐栏（"推荐"）**：卡片入口，`dailySongs` 数据。
  - 网易：`dailyRecommend()`；
  - QQ：`recommendSongs(30)` + `favoriteSongs()`（红心）经 `mergeDaily` 合并去重；
  - 酷狗：`everydayRecommend(30)` + `personalFM(12)` 合并，兜底搜索“热门歌曲”。
  - 聚合卡：`aggregateRecommendationCards`（跨平台推荐 + 网易红心雷达/私人漫游 + **酷狗私人漫游**——只要启用酷狗就显示）。
  - 加载路径两条：`load()` 主加载 + `fetchSnapshot(_:)` 快捷缓存快照（DiscoverCache），两处都要同步改动。
- **最近播放栏**：`recentPlayedSongs` = 聚合时 `player.history`，单平台时按 `source` 过滤；方块横滑卡片，点击从该位置播放。
- **排行榜栏**：三平台 `topLists`（网易 topLists / QQ topLists / 酷狗 topLists）。
- 数据有 `DiscoverCache` 快照缓存，切换页面不重复加载。

### 4.3 精选页 `RootView` 内的歌单浏览
- 左上角来源切换菜单（同主页交互）：**聚合 / 网易云 / QQ / 酷狗** 四种歌单模式，记忆上次选择。
- 统一 UI：搜索框 + 分类胶囊 + 双列歌单网格 + 下拉刷新 + 滚动到底翻页。
- 关键状态：`playlists`、`isLoading`、`isLoadingMore`、`hasMorePlaylists`、`nextOffset`、`pageSize=40`、`selectedCategory`、`featuredSource`。
- 加载入口：`load(reset:)`；翻页 `loadMoreIfNeeded()`；分类分派 `loadNetEase/loadQQ/loadKugou`；聚合 `loadAggregate`。
- **聚合歌单交叉显示**：`interleave(n,q,k)`，网易→QQ→酷狗→网易…轮流排列。
- **翻页失败策略（重要）**：首屏失败才设 `errorMessage`；翻页失败**静默置 `hasMorePlaylists=false` 保留已加载内容**，不弹“断网”。

### 4.4 播放 `PlayerManager`
`queue`、`history`（最近播放）、当前曲目、播放状态、音质。`player.history` 是“最近播放”数据源。

## 5. 平台接入（公开方法 + 分页 + 风控）

### 5.1 网易云 `NetEaseAPI`（weapi/eapi 加密，扫码/网页登录）
搜索（song/artist/album/playlist，均分页 offset）、歌单（playlistTracks / playlistMetadata / 用户歌单 userPlaylists）、`playlistSquare(cat,order,limit,offset)`（歌单广场分页）、`highQualityPlaylists`（精品）、`personalizedPlaylists` / `recommendResource` / `recommendedHomePlaylists`（个性化推荐歌单）、`topLists`、`dailyRecommend`、`personalFM`、`playRecord`（听歌排行）、`like`、`simiSongs` / `intelligenceList`（相似/智能推荐）、`newSongs`、`topPlaylists`、歌词（含翻译）、评论、歌手/专辑/艺人热门、歌单增删改。
> 网易是逆向最稳的平台，`playlistSquare` 可一直下拉。

### 5.2 QQ `QQMusicAPI`（musicu.fcg + client_search_cp + 官网 SSR）
- 搜索：歌曲/歌手/专辑用 **client_search_cp（t=0/1/8）**；**歌单 `searchPlaylists` 主用 client_search_cp t=3**（稳定），musicu search_type=3 兜底。
- 歌单广场：`allPlaylists(limit,offset)`（musicu GetPlayList 分页）→ 首屏失败回退 `hotPlaylists`（官网 SSR，**不分页**）→ 翻页回退 searchPlaylists。
- 其他：`favoriteSongs`（红心）、`like`、`topLists`/`topListSongs`、`recommendSongs`、`userPlaylists`、`playlistSongs`、歌词、评论、艺人/专辑热门、歌单增删、热搜词 `hotKeys`。
- **风控红线（极易踩坑）**：`musicu.fcg` 在你网络下**常被风控返回 2001**。凡是要稳定翻页的 QQ 数据，优先用 `client_search_cp`（家庭/移动/数据中心均可用）；`GetPlayList` 可能被风控，依赖兜底。

### 5.3 酷狗 `KugouMusicAPI`（上游 + 移动站/官网）
- `recommendPlaylists(limit,offset)`（歌单广场）：首屏优先上游 `special_recommend`，**后续页用移动站 `m.kugou.com/plist/index?json=true&page=N` 分页兜底（可一直下拉）**；首屏兜底官网正则。
- `searchPlaylists(limit,offset)`（分页）、`searchSongs/Artists/Albums`、`topLists`/`rankSongs`、`personalFM`、`everydayRecommend`、`userPlaylists`、`playlistSongs`、歌词、评论、热搜 `hotWords`、扫码登录。

### 5.4 群晖 NAS `SynologyAPI`
登录/登出、曲库 `librarySongs`、`songs/search/searchAll/searchAllVariants`、文件夹 `folderItems`、歌单 `playlists/allPlaylists/playlistSongs`、歌词、元数据编辑 `applyMetadata`（Audio Station tag_editor，见 docs/HANDOVER_CURRENT.md 的 NAS 章节）。
> 敏感信息（NAS 密码、`_sid`、Cookie/Token）只入 Keychain，不写入文档/日志/提交。

### 5.5 其他
本地音乐、第三方源导入/解锁（`ThirdPartySourceImportParser`、`UnblockService`）、聚合搜索 `AggregatedSearchService`。

## 6. 关键约定与易踩坑（本会话重点积累）

1. **QQ musicu 风控** → 稳定翻页用 `client_search_cp`（t=0 歌曲 / t=1 歌手 / t=3 歌单 / t=8 专辑）。新增 QQ 翻页功能时优先这个接口。
2. **精选页分页机制**：统一 `pageSize=40` + `nextOffset` + `hasMorePlaylists`。所有来源的 `loadXxx` 都接 `offset`；`hasMorePlaylists = !loaded.isEmpty && playlists.count > countBeforeMerge`（去重后仍增长才继续）。
3. **翻页失败静默停止**：`load(reset:false)` 的 catch 只置 `hasMorePlaylists=false`，不清空、不设 `errorMessage`（避免“断网”）。首屏失败才显示错误。
4. **聚合交叉**：`interleave(_ arrays: [Playlist]...)` 各平台轮流取，不要改回“按平台整块堆叠”。
5. **推荐栏合并**：`DiscoverView.mergeDaily([[Song]])` 按 `identityKey` 去重、保持顺序、`prefix(60)`。QQ/酷狗推荐栏都是“每日推荐 + 个性化”合并，改加载时两处（`load()` 与 `fetchSnapshot`）都要改。
6. **CoverImage 已支持 `width`/`height` 覆盖**（默认 nil 用 `size` 正方形）。做 2:1 等非正方封面时传 `width`/`height`，不要改回只支持正方形。
7. **主页板块顺序**：`SectionOrderStore`。改名会触发旧顺序迁移（旧值被过滤、追加新板块）。板块显示条件注意聚合/单平台分支（`isHomeAggregate`）。
8. **歌词行距**：`@AppStorage("atmusic.lyricSpacing")`，滑块 `4...40`（默认 16）。滑块范围/默认在此处，与播放器歌词共用。
9. **主页每日推荐卡片**：QQ 平台“每日推荐”卡用 `isWide: source == .qq`（2:1 长方形）；其他平台/聚合保持正方形。
10. **聚合页“酷狗私人漫游”**：显示条件已改为“启用酷狗就显示”（`homeProviders.contains(.kugou)`），不要加回“同时不含网易”。
11. **主页“歌单广场”已改名“最近播放”**：`personalized`（歌单）数据仍在 `load()` 加载并缓存，但主页不再展示（只展示最近播放）。如需彻底停掉该网络请求，需在 `load()` 中移除 personalized 相关加载——这是已知待办。
12. **版本号**：build 号由打包脚本自动递增；改代码前先确认当前 build，不要手工改乱 `project.pbxproj`/`project.yml`。

## 8. 已知问题 / 待办（接手后可继续）

1. **QQ `allPlaylists` 的 musicu GetPlayList 可能仍被风控**：build 47 已用 client_search_cp 兜底搜索，理论上能翻页；需在真机 QQ 精选页持续下拉验证。若某分类停住，记录停住的分类与页数再针对性处理。
2. **主页 `personalized`（歌单）仍在加载但未展示**：主页已改“最近播放”，`load()` 里网易/QQ/酷狗的 `personalized` 加载与缓存仍在跑，浪费请求。可考虑移除（用户认可后）。
3. **酷狗移动站分页稳定性**：`m.kugou.com/plist/index?page=N` 已作为酷狗翻页主力，需真机验证是否一直有内容；若某页空则 `hasMore` 自然结束。
4. **QQ 热门歌单（官网 SSR）本身不分页**：`hotPlaylists` 每次同一批，仅作首屏兜底；不要把它当分页源。
5. **聚合歌单第一页 QQ 可能来自热门歌单、后续来自歌单广场/搜索**：内容来源混合，若观感不佳可统一。
6. 平台接口为逆向，**随时可能变动或被风控**；改动前先在真机/日志确认接口现状。
